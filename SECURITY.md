# Security Policy

## Поддерживаемые версии

| Версия | Поддержка |
| ------ | --------- |
| 0.2.x  | активно |
| 0.1.x  | только критические уязвимости |

## Сообщить об уязвимости

Если вы нашли уязвимость безопасности (утечка токена, RCE, повышение
привилегий и т. п.), **не открывайте публичный issue**. Напишите автору
проекта в личное сообщение Telegram (см. README) или на email из
заявки.

Что приложить:

* Описание проблемы и сценарий воспроизведения.
* Версия проекта и среда (Fly.io / Railway / VPS / локально).
* По возможности — ваше предложение по исправлению.

Реакция:

* подтверждение в течение 72 часов;
* публикация фикса и CVE (если применимо) в течение 30 дней;
* благодарность в `CHANGELOG.md` (если согласны).

## Принципы безопасности проекта

1. Токен `BOT_TOKEN` и ключи LLM хранятся только в переменных
   окружения (Fly secrets / Railway variables / `.env` локально).
   В код они **не попадают**.
2. Персональные данные пользователей (имена в сертификатах, точки АНД)
   шифрования не требуют, так как ограничены функционалом сертификата
   и краудсорсингом мест публичного доступа.
3. Команды `/stats`, `/aed_admin` доступны только пользователю с
   `ADMIN_ID`. Сравнение делает `bot/handlers.py`.
4. CI прогоняет `ruff` и `pytest` на каждый PR. Зависимости фиксируются
   с pinned-версиями в `requirements*.txt`.
